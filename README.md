# 双语台词搜索

一个基于字幕时间轴的中英文台词搜索与片段播放工具。支持集数和说话人筛选、搜索结果前后文、分批加载、双语同步字幕和可恢复选中台词的链接。使用原生 JavaScript 和 Node.js，无运行时第三方依赖。

本项目采用轻量级规范驱动开发（SDD）：先明确需求和验收条件，再按设计与阶段任务实现，最后用自动测试和浏览器检查闭环。详见 [SDD 说明](docs/sdd.md)。

**克隆仓库后显示的是原创演示数据。** 本机导入的剧集字幕与视频保存在 Git 忽略的文件中，不随代码发布。演示数据没有视频，因此只能体验搜索和分享链接，不能验证片段播放。

## 启动

需要 Node.js 20 或更高版本。在项目目录运行 `npm start`，打开终端显示的 `http://localhost:4173`。运行 `npm test` 检查数据解析与搜索。开发验收本机视频时，可设置 `TBBT_LOCAL_MEDIA_PREVIEW=1` 后启动服务器；此模式只把本地剧集目录的视频地址改为同源 `/media/`，不修改 JSON 文件。

无需安装 npm 依赖。服务器只在本机监听，提供静态页面和可选的本地视频文件。克隆后直接运行即可使用演示数据。

GitHub Actions 会在每次推送和拉取请求时运行 `npm test`。

## 导入真实素材

1. 在项目目录的上级新建 `need/`，将你有权使用的中英文 SRT 放入，按 `Example S01E03.srt` 和 `Example S01E03-EN.srt` 命名，运行：

   `npm run import`

   脚本会自动识别 `S01E03` 这样的集数，更新该集台词并保留其他集。重复运行只替换同一集，不会生成重复结果。也可明确指定一集：`node scripts/import-srt.js "中文.srt" "English.srt" S01E03`。每集需要恰好一份中文 SRT 和一份文件名以 `-EN.srt` 结尾的英文字幕；若某集尚未准备齐全，请暂时不要将单个字幕放进 `need/`。中英文按时间重叠配对，导入后仍需抽查。导入结果写入本地 `data/dialogues.json` 和 `data/episodes.json`，两者均不会进入 Git。

2. 把浏览器可播放的 `S01E03.mp4` 放在本项目 `media/` 下。导入脚本会自动登记视频路径；若缺少 MP4，会明确提示，字幕仍可搜索。`media/` 及各类视频、字幕文件均被 Git 忽略。
3. 刷新页面。搜索中英文关键词，点结果播放。地址中的 `line` 参数可恢复选中的台词。

视频和字幕应当是同一剪辑版本。若原片是 MKV 且浏览器不支持，请用媒体转换工具转成 MP4（H.264 视频、AAC 音频）。如果已有 FFmpeg，可以使用 `ffmpeg -i input.mkv -map 0:v:0 -map 0:a:0 -c:v copy -c:a aac -b:a 192k -ac 2 -movflags +faststart media/S01E03.mp4`。只使用你有权使用和分发的素材。

## 当前本机素材状态

开发者本机的 `need/` 现有四集素材，导入后共 1602 条台词；这些素材与生成数据不随仓库发布。中文版字幕原本逐条附带英文，导入时仅保留中文行。S01E17 有两条台词未在独立英文字幕中找到重叠时间段：`S01E17-0347`、`S01E17-0389`，界面保留中文、英文留空。

## 验收

- 在新克隆中输入 `time` 或“时间”可看到演示记录；导入真实数据后可输入 `peanut` 或“花生”。输入不存在的词会看到空结果提示。
- 在“筛选集数”中选定某一集，结果只显示该集台词；切回“全部集数”恢复跨集搜索。结果初次显示 40 条，点击“再显示”逐批增加。
- 集数筛选按钮打开后可用方向键在选项间切换、Escape 关闭；只有实际换选项才更新列表。搜索词与集数筛选可以同时使用。
- 点击台词后，播放器根据该行时间定位，前后各保留两秒，时间到后暂停；如果媒体缺失，页面显示提示。
- 播放时字幕区域根据当前时间显示中文和英文。
- 复制分享链接并在新标签页打开，恢复该条台词。自动播放可能受浏览器限制，此时点播放即可。
- 把浏览器窗口缩窄至手机宽度：搜索后标题收起，结果仍可浏览；点击台词会打开底部播放器，关闭后回到原结果。桌面端结果与播放器并排显示。
- 结果中的匹配词会高亮，当前选中台词有明确标记；播放器的“上一句”“下一句”可在同一集内连续浏览。
- 搜索结果卡片可展开前后各两条字幕作为语境，也可从语境列表直接跳转播放某一句。前后文按该集字幕时间排序。
- 角色筛选读取台词记录的可选 `speaker` 字段。SRT 本身没有说话人信息时，界面会说明暂不可用；为台词添加人工核对的 `speaker` 值后，筛选器会自动生成角色选项，并可单独查看未标注台词。导入脚本不会猜测说话人。
- 需要补充说话人时，创建 `speaker-tags.json`，按稳定台词 ID 填写核对过的角色名，例如 `{"S01E02-0001":"Sheldon"}`。运行 `node scripts/apply-speakers.js speaker-tags.json` 会生成 `publish-candidate/dialogues.json`，不会覆盖本地原始台词。抽查后再上传该文件替换 COS 上的目录数据并触发 Vercel 重新构建；未标注的记录会保留为空，角色筛选可用“未标注角色”检查。
- 未搜索时首页居中展示搜索入口，并从当前导入的真实字幕按稳定台词 ID 展示六张精选片段卡片，包含集数、时间、中英文台词和从本机 MP4 在对应台词开始时间提取的真实画面。精选卡片点击后会在首页内容下方展开播放器并播放，不切到搜索结果列表；关闭播放器回到首页。当前 R2 `r2.dev` 视频响应没有 `Access-Control-Allow-Origin`，浏览器不能把跨域视频帧绘制到 Canvas，所以缩略图在本地离线生成并随正式 COS 构建发布，现有视频播放不需要开启 CORS。重新生成需有本机已导入的 `data/dialogues.json`、`media/S01E02.mp4` 等四个 MP4 以及 Python OpenCV：`python scripts/generate-featured-thumbnails.py`。演示数据或精选 ID 缺失时不伪造台词，会显示空状态。
- 每次点击台词会从开始前 2 秒播放，并在结束后 2 秒自动暂停一次。此后可继续播放整集；拖动“整集进度”会取消该次片段终点，字幕仍随当前播放时间变化。再次点台词或上一句、下一句会重新启用一次性自动暂停。

## 发布到 GitHub

### Vercel 静态演示站

运行 `npm run build`，把 Vercel 的构建命令设为 `npm run build`、输出目录设为 `dist`（Framework Preset 选 Other）。构建脚本只复制 `index.html`、页面所需的三个 `src` 文件，并将 `data/dialogues.example.json` 和 `data/episodes.example.json` 分别复制为 `dist/data/dialogues.json`、`dist/data/episodes.json`。`dist` 被 Git 忽略；演示站只展示原创演示台词，没有真实剧集视频。执行构建不会部署或上传内容。

构建前可运行 `npm test`；构建后检查 `dist` 的文件清单，确认恰好只有上述六个文件。每次构建会清理上次的 `dist` 输出，请勿在其中放置其他文件。

### 获授权素材的 COS + Vercel 发布候选流程

此流程与演示站构建分开，且只适用于已取得视频托管、公开播放及中英文台词检索展示授权的素材。默认 `npm run build` 仍只发布原创演示数据。不要把真实 `data/*.json`、`publish-candidate/`、`media/` 或原始字幕提交到 Git。

1. 将 `media/S01E02.mp4`、`S01E15.mp4`、`S01E16.mp4`、`S01E17.mp4` 上传到 COS 的同一目录，保持这些对象名。先验证 HTTPS 访问、`video/mp4`、HTTP Range 请求和浏览器播放；COS 对象的公开访问范围必须符合授权。
2. 在 PowerShell 中设置 `$env:COS_MEDIA_BASE_URL='https://你的桶域名/存放MP4的目录/'`，运行 `npm run prepare:cos`。脚本读取本地已导入的真实 JSON，核对四集及 MP4 是否存在，将视频地址改成 COS URL，并在被 Git 忽略的 `publish-candidate/` 中生成 `dialogues.json` 和 `episodes.json`。这一步不上传文件。
3. 人工检查这两个候选 JSON 的集数、台词内容与视频地址，再将它们上传到 COS 同一目录。可使用与 MP4 相同的目录；若分开存放，记下 JSON 所在目录 URL。两个 JSON 需要可被 Vercel 构建环境通过 HTTPS 读取。
4. 仓库中的 `vercel.json` 已将 Vercel 构建命令设为 `npm run build:cos`、输出目录设为 `dist`。默认从本项目使用的 COS 桶根目录读取两个 JSON；若文件位于其他目录，在 Vercel 项目中设置 `COS_CATALOG_BASE_URL` 为它们所在目录 URL。该命令在构建时从 COS 读取两个 JSON、核对四集、精选台词 ID 和已生成的六张缩略图，复制网页文件及缩略图到 `dist`，不把视频装进 Vercel 构建包。此步骤会让真实台词和由视频提取的精选画面作为 Vercel 静态文件公开，执行前务必核对授权范围。
5. 部署后分别验证中文与英文搜索、四集筛选、片段跳转、字幕同步和分享链接。若视频加载失败，检查 COS 对象的访问权限、`Content-Type: video/mp4`、分段请求响应，以及实际 MP4 编码；如果浏览器报告跨域问题，再按最小需要配置 COS CORS。

### 视频改由 Cloudflare R2 提供

四个 MP4 可分别上传为 `bbt-search-videos/media/S01E02.mp4`、`S01E15.mp4`、`S01E16.mp4`、`S01E17.mp4`。使用 rclone 分片上传并逐个核对远端文件大小；R2 凭据不进入仓库。上传成功后，在 R2 桶的 Settings 中连接可公开访问的自有域名；`r2.dev` 地址只适合临时测试。先对每个公开 MP4 URL 检查 HTTPS、`video/mp4`、HTTP 206 字节范围响应，以及浏览器能否播放与拖动。

当前 `npm run build:cos` 默认继续从 COS 读取 `dialogues.json` 和 `episodes.json`，但在构建产物中把四个视频地址改为本项目已验证的 R2 `r2.dev` 目录；COS 上的源 JSON 不变，也不会把视频复制进构建包。换成自有域名时，在 Vercel 项目环境变量中设置 `R2_MEDIA_BASE_URL=https://你的公开域名/media/`，然后重新构建。构建会检查四个视频是否返回 HTTP 206、`video/mp4` 和有效字节范围，且不能带强制下载的响应头；不满足时构建失败，避免发布无法播放的地址。切换后还需在实际浏览器验证四集的播放、拖动、字幕同步与分享链接。Cloudflare 的 `r2.dev` 地址有访问速率限制，适合验证和低流量演示，正式长期使用应连接自有域名。

若授权有限定地区或期限，静态公开文件无法自行实施可靠的地区/期限访问控制；应先设计受控分发方案，而不是执行上述公开部署。`npm run build:cos` 无法验证授权文件，也不会自动上传素材或修改 Vercel 设置。

本仓库只发布代码、文档和原创演示数据。提交前运行 `git status --short` 或 `git ls-files`，确认没有 `media/`、`need/`、SRT、MKV、MP4、`data/dialogues.json`、`data/episodes.json`、`.env` 或 `node_modules/`。普通 GitHub 仓库也不适合存放大视频。

上传代码仓库并不会自动发布可供他人观看的剧集视频。目前分享链接指向本机 `localhost`；如要提供公开网站，需要另外部署前端、设置可公开访问且有分发许可的视频地址，并检查分享链接的公网域名。尚未为本项目选择开源许可证；若希望他人复用代码，可在发布前确定许可证。
