# 实施方案与进度

## 技术方案

使用原生 HTML、CSS、JavaScript 和 Node.js 静态服务器，无外部依赖。SRT 导入脚本将字幕整理成 JSON；浏览器对小规模语料直接进行中英文关键词匹配。视频使用 HTML5 `<video>`，由 `timeupdate` 同步字幕并控制片段结束。稳定 ID 由集数和源字幕序号组成，链接用 `?line=ID` 恢复。

## 目录

- `index.html`、`src/`：界面、搜索与播放。
- `server.js`：本地静态文件服务器，支持视频 Range 请求。
- `scripts/import-srt.js`：字幕解析、按时间配对和导入。
- `data/dialogues.example.json`、`data/episodes.example.json`：公开仓库内的原创演示数据；同名无 `.example` 的文件由本地导入生成并被 Git 忽略。
- `media/`：用户自行放入视频，不纳入版本管理。
- `test/`：数据和搜索测试。

## 页面布局改造

桌面端采用搜索结果与常驻播放器双栏布局；手机端先显示搜索和结果，点选后以底部弹层播放，关闭弹层会暂停视频并将焦点还给所选结果。搜索时首屏标题收起，匹配词高亮，当前播放项有标识；播放器提供同集上一句、下一句。已在桌面及 375 × 812 手机视口检查布局，并在浏览器验证英文搜索、打开和关闭播放器、焦点返回及链接中的台词 ID。

第二轮改造：未搜索的首页将标题与搜索栏居中，下面展示精选片段；数据缺失时显示空状态。输入关键词或通过分享链接选中台词时切换紧凑布局。播放控制改为每次选中台词只在终点自动暂停一次；随后继续播放或手动调整“整集进度”可观看整集，字幕始终由视频当前时间驱动。浏览器已验证中文“花生”与英文 `peanut` 搜索、375 × 812 手机布局、播放器弹层与焦点返回、分享链接定位、S01E02-0002 在 8.52 秒自动暂停、继续播放越过该点、进度条输入跳至 480.5 秒时显示对应双语字幕并继续播放、再次点击同一台词重新启用自动暂停。内置浏览器对原生视频控件的鼠标拖动不稳定；自定义整集进度条的值变更已验证，仍建议在目标桌面和手机浏览器上手动检查拖动手势。

## 集数筛选流畅度修复

复现时，原生 `<select>` 打开后无 `change` 事件，结果数量、卡片和播放器均保持不变；内置浏览器的截图未捕获原生弹出菜单，但页面主体仍完整。由此判断点击时的短暂闪烁来自浏览器绘制原生菜单层，而非应用清空结果。改为按钮加浮层中的原生单选项：展开和关闭只切换浮层，只有选中不同集数才重算结果。单选项保留浏览器原生方向键操作，Escape 关闭后焦点返回筛选按钮，点击外部也可关闭。

浏览器验收：桌面及 375 × 812 手机视口下，打开菜单时结果与播放器布局未被清空；连续切换第 17、第 2 集和全部集数后数量正常。与 `peanut` 同时使用时，第 15 集为 0 条并显示空状态，第 16 集为 7 条，第 2 集为 2 条且选中台词仍标记“当前播放”。Codex 内置浏览器原生弹出层的瞬态绘制无法由页面截图完整捕获；本次修复绕开了该原生菜单，仍建议在常用浏览器复核是否还有显示驱动相关闪烁。

## 多集导入进度

已实现 `npm run import` 自动扫描上级 `need/` 的成对 SRT，以集数替换对应台词，保留其他集；重复运行不会累积重复记录。新集自动登记 `/media/集数.mp4`，缺视频时提示路径。导入前检查文件是否完整、字幕是否能解析及 ID 是否重复。当前四集共 1602 条台词，视频均已就绪；S01E17 两条中文记录无对应英文字幕，导入命令会列出其 ID。

## 多集检索体验

已加入集数筛选；搜索词与集数条件同时生效。结果每次显示 40 条，点击按钮再加载下一批，避免一次创建全部台词卡片。分享链接打开后，即使对应台词在后面的批次，也会将选中台词置于结果顶部。目录提示从数据中计算集数与台词数量，后续导入不需手动改文案。浏览器中已验证深链接置顶、筛选 S01E15 显示 405 条、加载下一批，以及无结果提示。

## 数据约定

每条记录为 `{id, episode, start, end, zh, en}`，时间单位秒；经人工核对的说话人可选填 `speaker`。`id` 采用 `S01E17-0001` 格式。导入时保持源字幕序号，以便重复导入后链接稳定。配对使用时间重叠，不能保证所有翻译完全对应，导入后应人工抽查。

## 2026-09-28 播放交互修复

发现：旧代码不检查 `play()` 拒绝时是否仍为当前选中台词，快速切换或暂停造成的 `AbortError` 会被误显示为视频地址、权限或编码故障。每次选中台词还会清空并重建整个结果列表，使按钮焦点丢失并增加绘制工作。R2 的 S01E02 公开视频实际返回 HTTP 206、`video/mp4` 和有效字节范围；此次没有发现该地址权限失败的证据。

修复：旧播放请求不更新新片段的提示；正常中断不报素材故障，必要时在跳转完成后仅重试一次，主动暂停或关闭手机播放器会使旧请求失效。跳转完成后才允许片段终点暂停，继续播放与手动进度跳转仍取消终点限制。当前可见结果只更新选中样式和标记，保留按钮焦点；字幕未变化时不重复重建节点。新增定位和缓冲提示，真正的网络、解码、格式错误仍显示，点击台词可重新加载已失败的同一视频。

验证：15 项自动测试通过，包含过期请求失败、AbortError 重试、主动暂停取消重试、限制重试次数和真实错误提示。用本地前端连接实际 R2 MP4 在浏览器验证 S01E02 和 S01E15 播放、快速切换较晚/较早台词、焦点保留；S01E02-0142 在 436.05 秒自动暂停，继续后超过 476 秒。手动用整集进度条跳至 126.9 秒后继续播放，双语字幕随时间更新。375×812 视口下点台词打开播放器，关闭后暂停并把焦点还给选中结果。真实素材未修改。

限制：这次代码尚未推送或部署，线上旧版不会自动获得本地修改。浏览器验收连接了线上 R2，但前端由本地提供；不等同于线上前端已验收。四个整集文件约 1.35–1.82 GiB，网络定位仍可能需要缓冲，交互修复不会提升源文件传输速度；当前 r2.dev 临时域名也不是正式长期分发方案。后续可独立规划较低码率视频或分段分发，并在目标手机及实际访问网络复核。

发现：正式台词记录目前只有稳定 ID、集数、起止时间和双语文本；SRT 导入器也没有说话人字段，因此不能准确推断出每句台词的角色。

验收：角色/集数/关键词组合筛选、未标注行、边界前后文和时间顺序均有自动测试；`scripts/apply-speakers.js` 根据独立的 ID 到角色映射生成候选台词目录，不会覆盖源文件，并拒绝未知 ID 和空角色名。总计 18 项测试通过。浏览器用当前真实数据确认前后文展开和直接播放控件；由于目前零条 speaker 标注，角色按钮显示“角色数据未导入”并说明字幕没有说话人标注，这是预期结果。要实际按角色筛选，需先人工核对并填写 `speaker-tags.json`，运行工具生成候选目录，检查后再更新 COS 并重新部署。
