# 实施方案与进度

## 技术方案

使用原生 HTML、CSS、JavaScript 和 Node.js 静态服务器，无外部依赖。SRT 导入脚本将字幕整理成 JSON；浏览器对小规模语料直接进行中英文关键词匹配。视频使用 HTML5 `<video>`，由 `timeupdate` 同步字幕并控制片段结束。稳定 ID 由集数和源字幕序号组成，链接用 `?line=ID` 恢复。

## 目录

- `index.html`、`src/`：界面、搜索与播放。
- `server.js`：本地静态文件服务器，支持视频 Range 请求。
- `scripts/import-srt.js`：字幕解析、按时间配对和导入。
- `data/dialogues.example.json`、`data/episodes.example.json`：公开仓库内的原创演示数据；同名无 `.example` 的文件由本地导入生成并被 Git 忽略。
- `media/`：用户自行放入视频，不纳入版本管理。
- `test/`：数据和搜索测试。

## 页面布局改造

桌面端采用搜索结果与常驻播放器双栏布局；手机端先显示搜索和结果，点选后以底部弹层播放，关闭弹层会暂停视频并将焦点还给所选结果。搜索时首屏标题收起，匹配词高亮，当前播放项有标识；播放器提供同集上一句、下一句。已在桌面及 375 × 812 手机视口检查布局，并在浏览器验证英文搜索、打开和关闭播放器、焦点返回及链接中的台词 ID。

第二轮改造：未搜索的首页将标题与搜索栏居中，下面展示四个由当前真实导入数据按稳定 ID 读取的精选片段；数据缺失时显示空状态。输入关键词或通过分享链接选中台词时切换紧凑布局。播放控制改为每次选中台词只在终点自动暂停一次；随后继续播放或手动调整“整集进度”可观看整集，字幕始终由视频当前时间驱动。浏览器已验证中文“花生”与英文 `peanut` 搜索、375 × 812 手机布局、播放器弹层与焦点返回、分享链接定位、S01E02-0002 在 8.52 秒自动暂停、继续播放越过该点、进度条输入跳至 480.5 秒时显示对应双语字幕并继续播放、再次点击同一台词重新启用自动暂停。内置浏览器对原生视频控件的鼠标拖动不稳定；自定义整集进度条的值变更已验证，仍建议在目标桌面和手机浏览器上手动检查拖动手势。

## 集数筛选流畅度修复

复现时，原生 `<select>` 打开后无 `change` 事件，结果数量、卡片和播放器均保持不变；内置浏览器的截图未捕获原生弹出菜单，但页面主体仍完整。由此判断点击时的短暂闪烁来自浏览器绘制原生菜单层，而非应用清空结果。改为按钮加浮层中的原生单选项：展开和关闭只切换浮层，只有选中不同集数才重算结果。单选项保留浏览器原生方向键操作，Escape 关闭后焦点返回筛选按钮，点击外部也可关闭。

浏览器验收：桌面及 375 × 812 手机视口下，打开菜单时结果与播放器布局未被清空；连续切换第 17、第 2 集和全部集数后数量正常。与 `peanut` 同时使用时，第 15 集为 0 条并显示空状态，第 16 集为 7 条，第 2 集为 2 条且选中台词仍标记“当前播放”。Codex 内置浏览器原生弹出层的瞬态绘制无法由页面截图完整捕获；本次修复绕开了该原生菜单，仍建议在常用浏览器复核是否还有显示驱动相关闪烁。

## 多集导入进度

已实现 `npm run import` 自动扫描上级 `need/` 的成对 SRT，以集数替换对应台词，保留其他集；重复运行不会累积重复记录。新集自动登记 `/media/集数.mp4`，缺视频时提示路径。导入前检查文件是否完整、字幕是否能解析及 ID 是否重复。当前四集共 1602 条台词，视频均已就绪；S01E17 两条中文记录无对应英文字幕，导入命令会列出其 ID。

## 多集检索体验

已加入集数筛选；搜索词与集数条件同时生效。结果每次显示 40 条，点击按钮再加载下一批，避免一次创建全部台词卡片。分享链接打开后，即使对应台词在后面的批次，也会将选中台词置于结果顶部。目录提示从数据中计算集数与台词数量，后续导入不需手动改文案。浏览器中已验证深链接置顶、筛选 S01E15 显示 405 条、加载下一批，以及无结果提示。

## 数据约定

每条记录为 `{id, episode, start, end, zh, en}`，时间单位秒。`id` 采用 `S01E17-0001` 格式。导入时保持源字幕序号，以便重复导入后链接稳定。配对使用时间重叠，不能保证所有翻译完全对应，导入后应人工抽查。
